## BLOCKER: New Pro subscribers get zero AI credits until first renewal

**Root cause:** `convex/stripeWebhooks.ts`'s `checkout.session.completed` handler (subscription branch, lines 88–115) only calls `upsertSubscription`. The only code path that grants/resets `aiCredits` is the `invoice.paid` handler, explicitly gated to `billing_reason === "subscription_cycle"` (lines 164–166) — which excludes the initial `subscription_create` invoice Stripe sends at checkout. This exclusion was a deliberate Phase 2 scope decision (documented in `02-RESEARCH.md` Open Questions, unit-tested to assert no `aiCredits` row is created for `subscription_create`), but the original architecture doc (`research/ARCHITECTURE.md:409`) specified `checkout.session.completed` should "grant initial credits" — that half of the design was dropped and never revisited when Phase 5 built the consumption UI on top of it.

**Impact:** A user who just paid for Pro sees a `0`/`null` credit balance in the toolbar badge, and their very first AI action throws `INSUFFICIENT_CREDITS`, opening the "buy more credits" dialog rather than delivering the paid-for 100-credit monthly quota — for up to ~1 month, until their first renewal.

**Affects:** PLAN-05, CRED-01, CRED-04 directly; PAY-01/PAY-02 indirectly (checkout "succeeds" but doesn't activate the plan's actual benefit).

**Fix location:** `convex/stripeWebhooks.ts` `checkout.session.completed` subscription branch — add a call to `aiCredits.resetCredits` (or an equivalent initial-grant mutation), or widen the `invoice.paid` gate to include `billing_reason === "subscription_create"` alongside `subscription_cycle`.
