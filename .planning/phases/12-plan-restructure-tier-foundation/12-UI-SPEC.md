## Spacing Scale

Declared values (must be multiples of 4) — matches existing usage on `pricing/page.tsx` and `SettingsPlanCard.tsx` exactly, no new scale introduced:

| Token | Value | Usage                                                                                    |
| ----- | ----- | ---------------------------------------------------------------------------------------- |
| xs    | 4px   | `gap-1` — badge icon/text gaps                                                           |

| md    | 16px  | `space-y-4` / `gap-4` — CardContent internal stack, Free/Premium card grid gap on mobile |

## Typography

Matches the existing, already-shipped scale on this exact page (`pricing/page.tsx`) and `SettingsPlanCard.tsx` — read directly from Tailwind utility classes in use, not invented:

| Role                   | Size               | Weight                               | Line Height |
| ---------------------- | ------------------ | ------------------------------------ | ----------- |
| Body                   | 16px (`text-base`) | 400 regular (`font-normal`, default) | 1.5         |
| Label / detail         | 14px (`text-sm`)   | 400 regular                          | 1.5         |

## Color

Read directly from `app/globals.css` (`:root` light theme — this app has no per-phase dark-mode scope change, dark theme values exist and are inherited unchanged):

| Role            | Value                                                                                                                | Usage                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `oklch(1 0 0)` — `#FFFFFF` (`--background`)                                                                          | Page background                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Secondary (30%) | `oklch(0.97 0 0)` — `#F7F7F7` (`--secondary` / `--muted`)                                                            | `Card` surfaces (both Free and Premium cards use the default `Card` background, which resolves to `--card`, visually the same near-white/light-gray family as `--secondary`/`--muted`)                                                                                                                                                                                                                                                                                                  |
| Accent (10%)    | `#7E10B2` (`--primary`, purple)                                                                                      | Reserved for: the Premium `Card`'s `border-primary` outline (marks it as the recommended/current plan), the primary CTA `Button` ("Upgrade to Premium"), the "Current plan" `Badge` (`variant="default"`, which resolves to `bg-primary`), the selected state of the Monthly/Annual `ToggleGroupItem` (`data-[state=on]:bg-accent` — uses the `--accent` token, which in this theme's light mode is `oklch(0.97 0 0)`, a neutral tint, **not** the purple `--primary` — see note below) |
| Destructive     | `oklch(0.577 0.245 27.325)` — renders as a saturated red, roughly equivalent to Tailwind `red-600` (`--destructive`) | Reserved for: the "Cancel subscription" `Button` (`variant="destructive"`) and its `AlertDialogAction` confirm button in `SettingsPlanCard.tsx` — both unchanged by this phase                                                                                                                                                                                                                                                                                                          |

**Important naming clarification (do not conflate):** This design system's `--accent` CSS variable (`oklch(0.97 0 0)`, a neutral gray tint used for hover/selected states like the `ToggleGroupItem`'s "on" state) is a _different_ token from the 10%-accent-color role in this design-quality framework, which maps to `--primary` (`#7E10B2`, the purple). When implementing the toggle, the selected Monthly/Annual segment will visually read as a light neutral fill (via `--accent`/`bg-accent`), not purple — this is correct, existing shadcn behavior and must not be overridden to use `--primary` instead (that would compete visually with the Card's `border-primary` and the CTA button for the single 10%-accent role this page already spends on the Premium card+CTA).

Accent reserved for (explicit, closed list): Premium card border (`border-primary`), "Upgrade to Premium" / "Subscribe" CTA button, "Current plan" badge (`Badge variant="default"`). Do not add `--primary` to any other element on this page (e.g., do not tint the "Save ~30%" badge purple — use `Badge variant="secondary"`, see Copywriting Contract).

## Interaction Contract — Monthly/Annual Toggle (D-02)

Not covered by the template's default sections but required for an executor to implement this phase's one new interactive element without ambiguity:

- **Component:** `ToggleGroup type="single" variant="outline" size="lg"` wrapping two `ToggleGroupItem` (`monthly` | `annual`), placed inside `CardContent`, above the price line, below `CardHeader`.
- **Default value:** `"monthly"` on first render (uncontrolled default or controlled `useState("monthly")` — matches D-02's "single Premium card" framing where the card should not open on the annual/discounted price unprompted).
- **`onValueChange`:** Radix `ToggleGroup` (single mode) can emit an empty string if the user clicks the already-selected item — guard against this (`if (value) setInterval(value)`) so the price line can never render blank.
- **State → UI mapping:** selecting `monthly` shows `6.99€ / month` and no savings badge emphasis; selecting `annual` shows `59€ / year` with the `Save ~30%` `Badge` visible next to the Annual segment (the badge is not hidden/removed on toggle — it's a static label on the Annual option, not a conditional callout, so it should render regardless of which state is currently selected, always anchored to the Annual `ToggleGroupItem`).
- **Checkout wiring:** `handleUpgrade` passes the current `interval` state through to `createCheckoutSession(locale, interval)` (extends the existing signature per RESEARCH.md's Code Examples section) — the toggle is pure client UI state, never itself calling Stripe or resolving a price ID (server-side allowlist resolution, per RESEARCH.md's Security Domain).
- **Accessibility:** Radix `ToggleGroup` provides roving-tabindex/arrow-key navigation and `aria-pressed` semantics out of the box — no additional ARIA wiring required. Ensure each `ToggleGroupItem` has visible text content (`Monthly` / `Annual`), not icon-only, so no `aria-label` override is needed.
