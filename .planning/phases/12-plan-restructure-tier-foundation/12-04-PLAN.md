<objective>
Implement and test the one-time migration of existing active Pro subscribers onto the new Premium monthly price, plus the guarded archival of the old Pro price.

Purpose: PLAN-09 and D-01. Stripe Price objects are immutable and swapping the app's env var only affects NEW Checkout Sessions — every existing `Subscription` keeps referencing the old 9 EUR Price forever with no error surfaced anywhere (12-RESEARCH.md Pitfall 1, the single highest business-risk item in this milestone). Because the old Pro price and the new Premium monthly price share the `month` interval, a plain `subscriptions.update` with `proration_behavior: "none"` swaps the item's price immediately without resetting the billing anchor and without generating a mid-cycle invoice — the subscriber's next natural renewal is the first time they pay 6.99 EUR, which is exactly D-01. No Subscription Schedule is required.

Output: `migrateProToPremium` and `archiveOldPriceIfUnused` in `scripts/stripeOps.ts`, full unit coverage with an injected fake client, and two CLI entrypoints wired to the `npm run stripe:migrate-premium` / `stripe:archive-old-price` entries created by plan 12-02.

This plan does NOT run anything against Stripe. Execution is plan 12-06.
</objective>

options: { idempotencyKey: string }
stripe.prices.update(priceId, { active: false }) -> archives a price (only `active` is mutable; amount is not)

  <action>
    Extend `scripts/stripeOps.ts` with an exported result interface `MigrationResult { migrated: string[]; skipped: string[]; failed: string[]; dryRun: boolean }` and `export async function migrateProToPremium(stripe: Stripe, params: { oldPriceId: string; newPriceId: string; dryRun?: boolean }): Promise<MigrationResult>`.

    Implementation:
    1. Guard first: if `oldPriceId` or `newPriceId` is empty, or if they are equal, throw before touching Stripe — migrating a price onto itself is always an operator error.
    2. Iterate `for await (const subscription of stripe.subscriptions.list({ price: params.oldPriceId, status: "active", limit: 100 }))`. Stripe is the authoritative enumeration source; Convex's `subscriptions` table has no `priceId` field and must not be consulted.
    3. `const currentItem = subscription.items.data[0]`. If it is undefined, `console.error("migrateProToPremium: subscription has no items", subscription.id)`, push the id to `failed`, and continue.
    4. If `currentItem.price.id === params.newPriceId`, push to `skipped` and continue — this application-level check, not the Stripe idempotency key, is what makes the script safe to re-run beyond the 24-hour key-retention window.
    5. If `dryRun`, push to `migrated` and continue without calling Stripe.
    6. Otherwise call `stripe.subscriptions.update(subscription.id, { items: [{ id: currentItem.id, price: params.newPriceId }], proration_behavior: "none" }, { idempotencyKey: `premium-migration-${subscription.id}` })` inside a try/catch. On success push to `migrated`; on failure `console.error("migrateProToPremium: subscription update failed", subscription.id, err)`, push to `failed`, and continue the loop — one bad subscriber must never abort the run.
    7. Return the result including `dryRun: params.dryRun === true`.

    Never omit `items[0].id`: without it Stripe ADDS a second parallel item and the subscriber is billed on both prices. Never pass a `proration_behavior` other than `"none"` and never pass `billing_cycle_anchor` — D-01 requires the current cycle to complete untouched at the old amount.

Build subscription fixtures with the real shape (`{ id: "sub_1", items: { data: [{ id: "si_1", price: { id: "price_old" } }] } }`) and make `subscriptions.list` an async generator so `for await` works. Assert `toHaveBeenCalledWith` on the exact three arguments of `update`, including the idempotency-key string.
