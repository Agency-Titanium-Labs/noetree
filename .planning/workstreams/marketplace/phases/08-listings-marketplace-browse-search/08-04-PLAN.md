browse handler:

1. numItems = clamp(Math.floor(args.paginationOpts.numItems), 1, LISTING_LIMITS.PAGE_SIZE_MAX); opts = { ...args.paginationOpts, numItems }.
2. q = args.q?.trim().slice(0, LISTING_LIMITS.SEARCH_QUERY_MAX) or undefined if empty; tag = args.tag?.trim().toLowerCase() or undefined if empty or longer than TAG_MAX_LENGTH (return an empty done page for over-long tags).
3. q && !tag: ctx.db.query("listings").withSearchIndex("search_text", s => s.search("searchText", q).eq("status", "published")).paginate(opts); map page through toPublicListing. Sort is ignored (relevance only — Pitfall 2; UI shows "Relevance").
4. q && tag (D-13 honored literally; replaces research A3's take(256) in-memory filter, so there is no result cap and pagination works): ctx.db.query("listingTags").withSearchIndex("search_text_by_tag", s => s.search("searchText", q).eq("tag", tag).eq("status", "published")).paginate(opts); docs = await Promise.all(page.map(r => ctx.db.get("listings", r.listingId))); keep non-null with status "published"; map toPublicListing; return { ...result, page }. Relevance order, sort ignored (same as step 3). Each listing has exactly one listingTags row per tag, so no dedupe is needed.
5. !q && !tag: index by sort — newest: by_status eq published order desc; price_asc: by_status_and_priceCents eq published order asc; price_desc: same index order desc; popular: by_status_and_salesCount eq published order desc (implicit \_creationTime gives newest-first ties, A1). paginate(opts), map toPublicListing.
6. !q && tag: listingTags index by sort — newest: by_tag_and_status_and_listingCreatedAt eq tag, eq published, desc; price_asc/price_desc: by_tag_and_status_and_priceCents asc/desc; popular: by_tag_and_status_and_salesCount_and_listingCreatedAt desc. paginate(opts); docs = await Promise.all(page.map(r => ctx.db.get("listings", r.listingId))); keep non-null with status "published"; map toPublicListing; return { ...result, page }.
