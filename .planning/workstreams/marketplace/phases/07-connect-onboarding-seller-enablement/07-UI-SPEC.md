## Interaction States

Four render states for `SettingsSellerCard`, driven entirely by `useQuery(api.connectAccounts.getMyConnectStatus, ...)` (reactive, webhook-driven — no polling, no optimistic state per D-08):

| State                                  | Trigger                                                       | Badge                                              | Body copy               | Action button                                                |
| -------------------------------------- | ------------------------------------------------------------- | -------------------------------------------------- | ----------------------- | ------------------------------------------------------------ |
| **Loading**                            | `isPending` on the Convex query                               | none                                               | `Skeleton` (`h-6 w-40`) | none                                                         |
| **No account yet** (entry point, D-01) | Query returns `null` (no `connectAccounts` row for this user) | none                                               | `sellerNotStartedBody`  | `becomeSellerCta` (`variant="default"`)                      |
| **Pending**                            | Row exists, `status === "pending"`                            | `variant="secondary"` — `sellerStatusPending`      | `sellerPendingBody`     | `resumeOnboardingCta` (`variant="default"`)                  |
| **Active**                             | Row exists, `status === "active"`                             | `variant="default"` — `sellerStatusActive`         | `sellerActiveBody`      | none (D-03: exactly one action only when pending/restricted) |
| **Restricted**                         | Row exists, `status === "restricted"`                         | `variant="destructive"` — `sellerStatusRestricted` | `sellerRestrictedBody`  | `updateDetailsCta` (`variant="default"`)                     |

Notes:

- The "No account yet" state is **not** one of D-03's three badge states — it is the pre-onboarding entry point required by D-01/D-02 ("Become a seller" visible to all users immediately). It shows no badge, matching that no Stripe account exists yet to have a status.
- All three CTA buttons (`becomeSellerCta`, `resumeOnboardingCta`, `updateDetailsCta`) call the **same** underlying server action, `createConnectOnboardingLink()` (per 07-RESEARCH.md Pattern 1) — only the label differs per D-03/07-RESEARCH.md Pattern 1. None are destructive; all use `Button variant="default"`, matching `SettingsPlanCard`'s non-destructive CTAs (`upgradeCta`, `resumeCta`).
- Per D-08: there is no fifth "verifying" state after the Stripe `return_url` redirect. Landing back on `/settings` after Stripe's hosted flow shows whatever the `connectAccounts` row already says (`Pending` by default, until the webhook patches it) — no `searchParams`-driven UI branch.
- Error state (server action throw, e.g. Stripe API failure during `createConnectOnboardingLink`): inline text below the button, `text-sm text-destructive`, matching `SettingsPlanCard`'s existing `error`/`actionError` pattern exactly (local `useState` in the client component, not a toast).

## Color

Declared values — reuses the existing CSS custom-property theme (`app/globals.css`) and existing `Badge`/`Button` variants only. No new color tokens.

| Role            | Value                                                                                  | Usage                                                                                                                                                                     |
| --------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `--background` / `--card` (`oklch(1 0 0)` light / `oklch(0.145 0 0)` dark)             | Page background, card surface                                                                                                                                             |
| Secondary (30%) | `--secondary` (`oklch(0.97 0 0)` light / `oklch(0.269 0 0)` dark)                      | `Badge variant="secondary"` (Pending state), muted text (`text-muted-foreground`)                                                                                         |
| Accent (10%)    | `--primary` (`#7e10b2`)                                                                | Reserved for: `becomeSellerCta`/`resumeOnboardingCta`/`updateDetailsCta` buttons (`Button variant="default"`), `Badge variant="default"` (Active state badge only)        |
| Destructive     | `--destructive` (`oklch(0.577 0.245 27.325)` light / `oklch(0.396 0.141 25.723)` dark) | `Badge variant="destructive"` (Restricted state badge only) and error text (`text-destructive`) — **not** used on any button in this phase (no destructive action exists) |

Accent reserved for (explicit list, per contract — never "all interactive elements"):

1. The three onboarding-link CTA buttons (`becomeSellerCta`, `resumeOnboardingCta`, `updateDetailsCta`) — all three, same primary treatment, since all three route to the identical underlying action.
2. The `Active` status badge (`Badge variant="default"`) — signals the one positive/current state, mirroring `pricing/page.tsx`'s existing use of `Badge variant="default"` for the current/active plan.

No new "success/green" color is introduced for the Active state — the codebase has no existing success/green token (confirmed via grep across `components/` and `app/`), and D-03 explicitly restricts this to a simple 3-state badge without a detailed capability breakdown, so reusing the existing `default` (primary) badge variant for "Active" — consistent with how `pricing/page.tsx` already marks the current/active plan — avoids introducing an unbudgeted fourth badge color.

## Copywriting Contract

All copy keys live under the existing `Settings` i18n namespace (`messages/en.json` / `messages/fr.json`), matching the tone and sentence length already established by `planCardTitle`/`creditsCardTitle` and sibling keys. English source strings below (French translation is an implementation task, not a UI-SPEC concern):

| Key                      | Copy                                                                                                      | Notes                                                                                                              |
| ------------------------ | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `sellerCardTitle`        | "Selling"                                                                                                 | `CardTitle`, parallel to existing one-word titles `"Plan"` / `"Credits"`                                           |
| `sellerNotStartedBody`   | "Sell your notes and earn money from buyers."                                                             | Shown only in the "No account yet" state (D-01 entry point), above `becomeSellerCta`                               |
| `becomeSellerCta`        | "Become a seller"                                                                                         | D-01/D-02 exact label                                                                                              |
| `sellerStatusPending`    | "Pending"                                                                                                 | Badge label                                                                                                        |
| `sellerPendingBody`      | "Finish onboarding with Stripe to start selling."                                                         | Shown above `resumeOnboardingCta`                                                                                  |
| `resumeOnboardingCta`    | "Resume onboarding"                                                                                       | D-03 exact label                                                                                                   |
| `sellerStatusActive`     | "Active"                                                                                                  | Badge label                                                                                                        |
| `sellerActiveBody`       | "You're ready to sell notes."                                                                             | No action button in this state (D-03)                                                                              |
| `sellerStatusRestricted` | "Restricted"                                                                                              | Badge label                                                                                                        |
| `sellerRestrictedBody`   | "Stripe needs more information before you can continue selling."                                          | Shown above `updateDetailsCta`                                                                                     |
| `updateDetailsCta`       | "Update details"                                                                                          | D-03 exact label                                                                                                   |
| `sellerActionError`      | "Something went wrong starting onboarding. Please try again, or contact support if this keeps happening." | Mirrors existing `actionError` string verbatim in tone/structure; shown on `createConnectOnboardingLink()` failure |

Primary CTA for this phase: **"Become a seller"** (first-time entry point) / **"Resume onboarding"** (returning-pending) / **"Update details"** (restricted) — all three are the same underlying action per 07-RESEARCH.md Pattern 1, labels differ only by state.

Empty state: not applicable in the traditional list-emptiness sense — the card always renders exactly one of the four states above; the closest analog is the "No account yet" state, covered by `sellerNotStartedBody` + `becomeSellerCta`.

Error state: `sellerActionError`, rendered exactly like `SettingsPlanCard`'s existing inline `error` paragraph (`text-sm text-destructive`, local component state, no toast).

Destructive actions: **none in this phase.** No delete/cancel/disconnect action exists for a seller's Connect account (Stripe onboarding is additive and idempotent per D-07 — every click just generates a fresh Account Link). No confirmation dialog is needed anywhere in this card, unlike `SettingsPlanCard`'s `cancelCta` → `AlertDialog` pattern.
