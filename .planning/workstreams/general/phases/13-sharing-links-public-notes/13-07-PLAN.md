  <name>Task 2: Manual browser verification of sharing flows</name>
  <what-built>Owner-side Share dialog (Link and Public tabs), visitor page /s/[token], public page /p/[noteId], and all backend enforcement.</what-built>
  <how-to-verify>
Start the app (`rtk npm run dev` and `rtk npm run convex`, ensuring the Convex deployment has the new schema). Use two browser contexts: A = normal window signed in as the note owner; B = private/incognito window signed out.
1. In A, open a note with at least one sub-note, open Share, go to the Link tab. Click Create link with View only. Expect: URL field appears (…/s/<long token>), Copy link shows "Copied" for ~2 s. (This also proves the createLink action propagates the caller identity.)
2. Paste the URL in B. Expect: title + rendered content, read-only, no sidebar, no toolbar, no sign-in banner, footer "Made with Noetree". Sub-notes are NOT reachable from this page (D-02).
3. In A change the role to Can edit. Expect the URL is unchanged. Reload B: expect the "Sign in to edit this note." banner, content still readable.
4. In B click "Sign in to edit", sign in with a different Clerk user. Expect: you return to the same /s/ URL, editor becomes editable without reload, typing and waiting ~3 s shows Saving... then Saved, and the change appears in A. The note does NOT appear in the second user's sidebar (D-10).
5. In A click Revoke link and confirm (focus starts on "Keep link active"). Expect the B page, still open, immediately shows "This link isn't available". Reload B: same state. Create a new link: the new URL differs from the old; the old URL still shows unavailable.
6. In A open the Public tab: read the cascade warning, switch on "Make this note public". Expect "This note is now public.", a /p/<noteId> URL, and the Public badge. Open it in B: read-only note plus a "Sub-notes" list; click a sub-note and it opens at /p/<childId>. Page source/`<head>` contains robots noindex.
7. In A, open the sub-note's Share dialog Public tab: expect the switch disabled with "Public because a parent note is public." Move the sub-note out of the public subtree (drag to another root note): B's sub-note page flips to unavailable.
8. In A switch the public note off and confirm ("Keep note public" is the safe button). Expect B's /p/ page flips to unavailable.
9. Repeat step 1 and step 6 with an account that has NO subscription (Free) and one with an active subscription (Premium): identical behavior, no upgrade prompts.
10. Sign in as a user who only has an edit-role share on a note: its Share dialog shows only the People content (no Link/Public tabs).
  </how-to-verify>
