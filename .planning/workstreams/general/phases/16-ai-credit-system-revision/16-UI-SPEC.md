# Phase 16 — UI Design Contract

> Visual and interaction contract for the AI Credit System Revision. Generated by gsd-ui-researcher (auto/chain mode, no user questions). Reuses the existing design system and Phase 15 conventions. No new tokens, fonts or libraries. Sources: 16-CONTEXT.md (D-01..D-12), existing `EditorToolbar`, `CreditsExhaustedDialog`, `SettingsCreditsCard`, `AiCredits` i18n namespace.

| sm    | 8px   | Gap between pack cards, menu item inner gap (`gap-2`), bucket-split row gap |
| md    | 16px  | Pack card padding (`p-4`), dialog content gaps, Card `space-y-4`            |

| 2xl   | 48px  | not used                                                                    |
| 3xl   | 64px  | not used                                                                    |

Exceptions: toolbar AI menu items and pack buttons use `min-h-11` (44px) on mobile, `md:min-h-9` on desktop (same convention as Phase 14/15). Cost chip height is 20px (`h-5`), a Badge-intrinsic size, not a spacing token.

Layout:

- Pack picker: `grid grid-cols-1 gap-2 sm:grid-cols-3`. Each pack is a `Card`-styled form submit button region (`rounded-lg border p-4`), stacked on mobile, 3 columns from `sm`.
- In `CreditsExhaustedDialog` the picker sits between description and footer; dialog keeps `DialogContent` default width but gets `sm:max-w-xl` to fit three columns.

## Color

Existing theme tokens only.

| Role            | Value                             | Usage                                                                                                                      |
| --------------- | --------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `--background`                    | Page, dialog and menu surfaces                                                                                             |
| Secondary (30%) | `--muted` / `--card` / `--border` | Pack cards at rest, cost chips (`Badge variant="secondary"`), bucket-split row, history rows                               |
| Accent (10%)    | `--primary` #7e10b2               | See reserved list                                                                                                          |
| Destructive     | `--destructive`                   | Not used. Insufficient credits is not destructive; it uses muted/disabled styling. Only generic checkout/action error text |

Accent reserved for:

1. The `Buy` button inside the recommended pack (Boost, 5€/300) in `CreditPackPicker` (single accent CTA per picker; the other two packs use `variant="outline"`).
2. The "Upgrade to Premium" button in `CreditsExhaustedDialog` for Free users (secondary to pack purchase; see Interaction, uses `variant="outline"` when packs are shown, so accent stays only on Boost). Final rule: at most ONE accent button visible per surface.
3. The 2px `border-primary` ring on the recommended pack card.

Everything else (toolbar Sparkles trigger, menu items, cost chips, balance badge, history) uses ghost / outline / secondary variants and muted foreground. Insufficient-balance menu items use `opacity-50` and `text-muted-foreground`.

Primary visual anchor: in the exhausted dialog and the Settings card, the Boost pack card (accent border + accent Buy button). In the editor toolbar the anchor is the `Sparkles` trigger with the balance badge, unchanged and unaccented.

## Interaction Contract

### 1. Toolbar AI actions (D-05, D-06, D-10)

- Replace the single Sparkles `ToolbarButton` with a `DropdownMenu` whose trigger is the same ghost icon button (`Sparkles`, `aria-label` = `AiCredits.menuAria`, tooltip `Editor.tooltips.aiAction` reworded to "AI actions"). The balance `Badge` stays immediately right of it, unchanged.
- Menu has three `DropdownMenuItem`s, one per cost tier, in ascending cost order:
  1. Generate suggestion — `Sparkles` icon — cost chip "1"
  2. Analyze semantics — `Brain` icon — cost chip "3"
  3. Generate note links — `Link2` icon — cost chip "5"
- Each item: icon (16px), label (14px/400), then right-aligned cost chip `Badge variant="secondary"` 12px/600 with `Coins` 12px icon + number (e.g. "3"), and `aria-label` = `AiCredits.costAria` ("{count} credits"). Label and chip are the visible cost display before the user acts.
- Insufficient balance (balance < cost, from the summed buckets, D-03): item gets `aria-disabled="true"`, `opacity-50`, is NOT `disabled` for pointer events so it can show a tooltip; hover/focus tooltip `AiCredits.insufficientTooltip` ("Not enough credits: needs {cost}, you have {balance}"). Selecting it still calls the server (server is authoritative; the client never blocks) and, on `INSUFFICIENT_CREDITS`, opens `CreditsExhaustedDialog`. A visually-disabled item that is activated therefore routes to the dialog, which is the intended recovery path.
- Pending: while `runAiAction` is pending the trigger shows `Loader2 animate-spin` in place of `Sparkles` and menu items are `aria-disabled`.
- Success: `sonner` toast `AiCredits.actionSuccess` ("Done. {cost} credits used."). Because actions are placeholders this phase, toast copy is neutral and does not claim a result.
- The client sends only the action key (`basic`, `semantic`, `linking`), never an amount (CRED-10).
- Balance badge tooltip stays `badgeTooltip`; it shows the SUM of both buckets (D-03).

### 2. Settings credits card (D-03, D-11)

- Title unchanged. Balance line: total (sum of buckets), `text-base`, number 600.
- Below the total, a muted 14px split row: "{monthly} monthly · {purchased} purchased" with a short caption under it: "Monthly credits reset on {date}. Purchased credits never expire." (reset date = next UTC month start for Free; billing period end for Premium, via existing subscription data; if unknown omit the date clause).
- Section "Buy credits": heading 14px/600, then `CreditPackPicker` with three packs. Visible to Free and Premium (D-11).
- Purchase history (existing top-up list) retained below, now showing pack name + credits (row: date left, "+{credits}" right). Empty state reuses `topupHistoryEmpty*` with updated body.
- Loading: existing `Skeleton` pattern, extended with a second `h-24` skeleton block for the picker.

### 3. CreditPackPicker (shared)

Three pack cards, each: pack name (12px/600 label), price (20px/600, e.g. "2€"), credit count (12px/400 muted, "100 credits"), a unit hint line is NOT shown (avoid derived math), and a full-width `Button` "Buy". Order: Découverte, Boost, Pro (ascending). Boost carries a "Best value" tag (`Badge variant="secondary"`) and the accent treatment. Each Button is inside its own `<form action={createCreditPackCheckoutSession}>` with a hidden `pack` input (`decouverte` | `boost` | `pro`); the server maps pack key to Stripe price ID (never trust client price or amount). Submit pending: `Loader2` + disabled for that card only. Whole card is not clickable; only the Button is, to keep one tab stop per pack. `aria-label` on Button: "Buy {name}, {credits} credits for {price}".

### 4. CreditsExhaustedDialog (D-10, D-11)

- Dialog is no longer tier-branched for the purchase path: both tiers see the pack picker.
- Free users additionally see a text-link style `Button variant="outline"` "Upgrade to Premium" in the footer next to "Maybe later"; Premium users see only "Maybe later".
- Description is tier-aware: Free body explains the monthly quota resets on the 1st (UTC) and that packs never expire; Premium body explains reset at next billing cycle.
- Focus: initial focus on the dialog title region via Radix default; Escape and "Maybe later" close.

### 5. States

- Loading balance: badge shows `Skeleton` 24px wide until first value (existing default 0 must not flash as "0 credits"; render skeleton while `credits === undefined`).
- Checkout error (server action failure): inline `text-sm text-destructive` below the picker with `AiCredits.checkoutError` copy; the picker stays usable.
- Action error (non-credit failure): toast error `AiCredits.actionError`.
- Webhook latency: after returning from Stripe success URL the balance updates reactively; no manual refresh control.

### 6. Accessibility

Menu is keyboard operable (Radix); cost conveyed in text and `aria-label`, not by color alone; disabled-looking items expose `aria-disabled` plus tooltip text; 44px touch targets on mobile; focus rings from shadcn defaults; pack grid uses `role="group"` with `aria-label` = `AiCredits.packsGroupAria`.
