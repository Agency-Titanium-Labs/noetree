## Open findings

### F-01 HIGH (unverified, needs a live check): settle may fail on an expired Clerk JWT, turning completions into free refunds

route.ts:28-44 builds ONE ConvexHttpClient with `setAuth(token)` and uses it for both `beginRun` (start) and `settleRun` (up to 100 s later, after the stream). `settleRun` is secret-guarded and does not need identity, but if the Convex deployment rejects an expired JWT on any request that carries one (Clerk `convex` template tokens default to about 60 s), settle throws, executeRun swallows it (executeRun.ts:86-90), and the reaper refunds the run after 5 minutes. Result: any answer taking longer than the token lifetime (long generations; timeout at 100 s) is free, and the user has the full text. Tests do not cover it (they run begin/settle in-process with no token expiry).
Fix: create a second `ConvexHttpClient` with no auth for `settleRun` (the secret is the credential). Optionally confirm the Clerk template lifetime. Add a test that settle works with no auth token.

### F-02 MEDIUM: per-message cap bypassed by merging, and no output token cap

chatPrompt.ts:72-74 concatenates consecutive same-role turns AFTER each is sliced to 8000 chars, so ~64 consecutive user messages (body limit 512 000 chars, chatHandler.ts:30) yield a single ~512k char (about 128k token) user turn for one flat credit; the 6-exchange cap counts turns, not size. Also gatewayProvider.ts:17 sets no `maxOutputTokens`, so output is bounded only by the 100 s timer.
Fix: cap total characters of the assembled history and the merged turn (for example 24-32k chars total, dropping oldest), or do not merge but reject consecutive same-role input; pass `maxOutputTokens` to streamText.

### F-03 LOW: no CSRF defence in depth

The handler reads `req.text()` regardless of Content-Type and checks no Origin/Sec-Fetch-Site. Clerk's `__session` cookie is SameSite=Lax, so a cross-site POST normally carries no session; same-site (sibling subdomain) attackers could trigger credit spend, but cannot read the answer.
Fix: require `content-type: application/json` and reject `sec-fetch-site: cross-site` (or Origin not equal to own origin) before auth.

### F-04 LOW (accepted-risk candidate): abort before first token is refunded

A client that aborts before the first token pays nothing but may still incur upstream input-token cost. Bounded by the 10/min bucket and 3 in-flight cap. Document as accepted; consider logging abort rate per user.
