## OPEN

### O-1 (HIGH, CTX-05 / D-06): purchased-branch exclusion is bypassable by moving or duplicating purchased notes

Only the copy ROOT carries `purchaseId` (`delivery.ts:142`, D-08). The builder detects purchased content solely by that flag on the current note or an ancestor (`aiContext.ts:254,278`). The buyer owns every copied note and can:

1. Re-parent a purchased sub-note out of the copy (`notes.ts` `updateParentNote` ~845, `moveNote` ~883, `updateNote` parentNote). The moved note has no flagged ancestor, so AI runs on it and its text is sent to the provider.
2. `duplicateNote` (`notes.ts:779`) a purchased root or sub-note: `planCopy`/`writeCopy` strips `purchaseId` (written only if `opts.purchaseId`), so the copy is unflagged.
   Same weakness exists in `assertNotPurchasedContent` (listings.ts:288), but here it leaks seller content to a third-party LLM, which D-06 explicitly forbids ("including after the buyer edits it and including any sub-note").
   Fix (pick one): (a) in `delivery.ts` also flag every copied descendant (new optional `purchasedFrom`/`isPurchasedCopy` field on all notes of the copy; the builder refuses/excludes any note with it) and make `writeCopy`/`duplicateNote` propagate the flag; or (b) block `moveNote`/`updateParentNote`/`updateNote` re-parenting out of, and `duplicateNote` of, a purchased branch. Add tests for moved sub-note and duplicated root.

### O-2 (MEDIUM): context step runs before the rate limit and in-flight cap, with no throttle

`aiRuns.ts:188-231`. Refused calls (CONTEXT_TOO_LARGE, NOTE_NOT_OWNED, NOTE_NOT_FOUND, PURCHASED_CONTENT_EXCLUDED) consume no token, so an authenticated user (any tier for non-premium actions) can loop beginRun doing ~125 document reads, JSON parses and char-by-char escaping per call with no limit. Successful calls are metered; refusals are the free path. It is also a free oracle for the size of the user's own note (own data only, so not a confidentiality issue).
Fix: consume a rate token (or a separate cheap "refusal" bucket) before the context step, and refund-free; or move rate check before 3b while keeping debit after it.

### O-3 (LOW): Existence/structure oracle through crafted parent links

`updateParentNote`/`updateNote` let a user set their own note's `parentNote` to any note id (no check on the target). Then `beginRun` reveals: NOTE_NOT_FOUND vs `dropped: not_owned` (id exists), PURCHASED_CONTENT_EXCLUDED (the foreign note has a purchased ancestor), CONTEXT_TOO_LARGE (chain deeper than 64). Requires knowing the victim's note id (unguessable Convex id), no content or titles leak. Fix: do not report foreign ids in `dropped` (use counts or reason only), and validate parent ownership in the re-parent mutations.

### O-4 (LOW/WARNING, unregistered): collaborator-authored text is sent as "the user's own notes"

Ownership is by `note.owner`, not authorship. An editor of a shared note can write text into the owner's note (also copies of public notes), which then reaches the provider and may carry prompt injection. Escaping and the fixed statement make breakout structurally impossible, but the statement's "the user's own notes" wording is not strictly true and RGPD review is deferred (18-CONTEXT deferred ideas). Markdown links (`[x](https://...)`) are not defanged, only `![`. Phase 19 must sanitize LLM output rendering (no auto-loaded images, no raw HTML, links neutralised or confirmed).

### O-5 (INFO): Phase 19 integration constraints

- `beginRun` returns the full serialized context to the client; the Next route in Phase 19 must not trust a client-supplied context or noteId, and should re-derive or bind it server-side (the noteId is not stored on the `aiRuns` row, and a lost response of the claiming call cannot be replayed to recover the context).
- A very wide `childNotes` array makes `dropped` large (every id beyond the cap is reported); cap the returned `dropped` list.
- A transaction touching 125 large documents may hit Convex read limits and throw an untyped error (fails closed, no leak).
