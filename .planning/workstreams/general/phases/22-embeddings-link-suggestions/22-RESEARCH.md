## Convex vector index (checked in `convex/_generated/ai/guidelines.md`, `convex-test`)

- `ctx.vectorSearch(table, index, { vector, limit, filter })` exists **only in actions** (queries/mutations cannot). `limit` max 256 (1..256). Results are `{ _id, _score }`, so a follow-up `ctx.runQuery` resolves the documents.
- `filter` accepts `q.eq(field, value)` on declared `filterFields` and `q.or(...)` of the same field; **one field** for `eq` in `convex-test`. We filter by `owner` only (mandatory: this is the cross-user isolation, PITFALLS 13). Everything else (candidate set, ineligible notes) is filtered in code after the search.
- Dimension is fixed in the index (768). A vector of another length is not indexed. Max supported dimension is 4096, so 768 is well within.
- Index data is eventually consistent with writes made in the same action (documented: vector indexes update asynchronously). The action therefore searches **after** the upserts have committed in earlier mutations and never relies on read-your-writes inside one transaction. Production risk: a note embedded seconds ago may not appear yet; for the SOURCE note we never depend on the index (its vector is read from the table and used as the query), and candidates that are not yet indexed are simply missed for that run (re-run after a short wait; documented limit).
- `convex-test` implements `vectorSearch` as brute-force cosine over the table with the single-`eq` filter, so ranking, owner isolation and caps are testable offline.
- Vector storage is `v.array(v.float64())`; ~6 KB per note at 768 dims, well inside the 1 MiB document limit. Vector index reads are billed by index size, so the owner filter plus the 300-note cap per analysis also bounds cost.

## Metering reuse (no change to Phase 17 code)

- `aiRuns.beginRun` is a mutation that already does replay, kill switch, tier gate, in-flight cap, rate limit, debit and the reaper timer. A mutation may call `ctx.runMutation(api.aiRuns.beginRun, ...)`; it runs in the **same transaction** and keeps the caller's identity, so the debit and everything the reserving mutation does afterwards commit or roll back together. This lets `links.requestAnalysis` reserve with the existing code path and validate the note afterwards: if validation throws, the whole transaction (debit included) rolls back.
- `settle(ctx, runId, outcome)` is exported from `convex/aiRuns.ts`. The analysis writes its result rows and settles the run **in one mutation** (`finishAnalysis` / `failAnalysis`), so "result stored" and "run completed" cannot diverge. A refused/failed analysis refunds in the same transaction.
- Reaper backstop: if the action dies, the Phase 17 timer/cron refunds the run (`expired`). `finishAnalysis` first checks the run is still `reserved`; if the reaper already refunded it, nothing is stored and the analysis is marked refunded. The panel derives "refunded" from the run status too, so a crashed action never leaves the UI on "running".
- Action wall-clock budget = `MAX_RUN_DURATION_MS` (120 s) < `RUN_TTL_MS` (300 s), same invariant as Phase 19, so the reaper cannot refund a live analysis.

## Scope and bounds

- Eligible notes = rows owned by the caller (index `by_owner`), not `isPurchasedNote`, with non-empty extracted text. Foreign/shared notes are never read (the index is the owner's).
- Recency key = `updated_at` (ISO string, lexicographic order) else `_creationTime`. The scan pages `by_owner` metadata only (page size 50, hard scan ceiling 3000 notes; beyond it `truncated` is also true). At most 300 notes are embedded/compared (the source always included, then most recent first). `truncated` = eligible notes > 300 (or scan ceiling hit), stored on the analysis row for the UI.
- Embedding text = title + extracted text bounded to 6 000 chars (well below the model input limit, bounded cost). `contentHash` = SHA-256 over `model + title + text`, so a model change or any edit re-embeds, an unchanged note never does.
- Embedding batches of 32 inputs; a failed non-source batch is skipped and counted (`skippedCount`), a failed source batch or all-batches-failed fails the run and refunds.

## Injection safety (Phase 18 framing reused)

- Excerpts go through `escapeContextText` (exported from `convex/helpers/aiContext.ts`): `& < >` entities, hidden/bidi/confusable characters visible, `![` and `](` defanged. The prompt carries a fixed statement that note blocks are untrusted DATA (same wording family as `CONTEXT_STATEMENT`), each block with `title-len`/`body-len`, a fixed footer, and the instruction to answer with ONE plain sentence.
- **One model call per suggestion**, with only that source/target pair: an injected note can at worst skew its own sentence, never another suggestion's or the ranking (ranking is vector math done outside the model).
- Output is untrusted too: `sanitizeJustification` keeps the first sentence, strips control/bidi characters, Markdown/HTML/URLs, collapses whitespace and caps the length; it is stored and **rendered as React text** (no Markdown, no `dangerouslySetInnerHTML`). An empty result drops that suggestion.
- Suggested targets are validated server-side as notes owned by the caller (cross-user leak impossible: owner-filtered vector search + re-check at store time).

## Cost model

5 credits (`linking`, Premium) per analysis, shown before launch from the shared catalog. Real spend per run: at most 10 embedding calls (300 notes, only changed notes) + at most 8 tiny completions. Re-runs on unchanged notes embed only the source if edited.
