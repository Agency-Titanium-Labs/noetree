<findings_from_planning>
Facts already established while planning (do not re-derive; verify only where a task says so):

1. Tiptap 3.26.1 (node_modules/@tiptap/core/dist/index.js, `setEditable(editable, emitUpdate = true)`) emits an "update" event by default. providers/EditorProvider.tsx calls `editor.setEditable(isEditable)` in the "editable status" effect. On exitPreview, previewRef is cleared first, then the effect re-enables editing, which fires the update listener: it sets saveStatus "unsaved" and calls debouncedSave (3000 ms) -> onUpdateNoteContent -> api.notes.updateNoteContent. This matches the "Unsaved changes" label seen right after a restore and means every preview exit (and every restore) causes an extra note write ~3 s later.
2. providers/EditorProvider.test.tsx mocks the editor; its fake `setEditable` only flips `isEditable` and never calls the update listener, which is why the existing suite did not catch fact 1.
3. @convex-dev/react-query 0.1.0 (node_modules/@convex-dev/react-query/dist/esm/index.js): ConvexQueryClient subscribes a Convex `watchQuery` per TanStack query hash on the cache "added" event; each `watch.onUpdate` calls `queryClient.setQueryData(queryKey, prev => prev === undefined ? undefined : watch.localQueryResult())`. Updates are dropped when the TanStack entry has no data yet.
4. Convex's client contract: a mutation promise resolves only after the client has applied the query transition that includes the mutation's writes. So if the list subscription is live and the render path is correct, the new row must be renderable no later than `await restore(...)` returning in VersionPreviewBanner.onConfirm.
5. GAP-2: tsconfig.json (root) excludes `**/*.test.ts`, so root tsc never sees convex/noteVersions.test.ts. convex/tsconfig.json includes `./**/*`. Errors at lines 292/299 come from `type T = ReturnType<typeof convexTest>` (line 23): without the schema argument, convexTest's generic falls back to a schema-less data model, so `withIndex` only accepts system indexes. Error at line 689 comes from `pageAll(as: { query: (ref: typeof api.noteVersions.list, args: object) => ... })` (line 570): the hand-written structural type does not match TestConvex's overloaded `query`.
6. GAP-3: UI-SPEC line 110 says the Sheet stays open on desktop and closes on < sm. The banner buttons are right-aligned (`md:justify-between`) so on desktop they sit physically under the 448px Sheet panel, not just under the overlay; making the Sheet non-modal or raising the banner's z-index would not uncover them without moving the Sheet. The least invasive fix is to close the Sheet after a successful selection on all viewports (the History button re-opens it, and the panel keeps its query cache so reopening is instant).
</findings_from_planning>
